# Quiz Exam — техническая защита информации

Приложение для прохождения теста из **180 вопросов** с четырьмя вариантами ответа. Проверка выполняется только на сервере. Участнику показывается подтверждение отправки; результаты и правильные ответы видит только администратор.

## Быстрый запуск

Нужен **Node.js 24+** (SQLite встроен в Node.js; отдельный сервер БД не нужен).

```bash
npm install
cp .env.example .env
```

Укажите в `.env` свой длинный уникальный пароль (не менее 12 символов):

```dotenv
ADMIN_PASSWORD=ваш-длинный-уникальный-пароль
PORT=3000
HOST=0.0.0.0
DATABASE_PATH=./data/quiz.sqlite
COOKIE_SECURE=false
TRUST_PROXY=0
```

```bash
npm start
```

- Тест: **http://localhost:3000/**
- Админ-панель: **http://localhost:3000/admin**
- Разработка с перезапуском: `npm run dev`.
- Воспроизводимая установка с lockfile: `npm ci`.

В подготовленной облачной рабочей копии `.env` может уже существовать с автоматически созданным локальным паролем. Не перезаписывайте свой файл вслепую; измените `ADMIN_PASSWORD` и перезапустите приложение. `.env` и база не попадают в Git.

## Архитектура и файлы

```text
server/
  index.js                 запуск, конфигурация из окружения
  app.js                   Express API, SQLite, сессии администратора
  questions.js             загрузка и проверка вопросов и ключа
  data/
    source.txt             исходный прикреплённый файл
    questions.json         180 вопросов, 720 вариантов, исходный порядок
    answer-key.json        серверный ключ: ID вопроса → A/B/C/D
    ANSWER_KEY_REVIEW.md    таблица ключа для проверки владельцем
public/
  index.html, app.js       прохождение, localStorage, подтверждение отправки
  admin.html, admin.js     вход, список, поиск, сортировка, детали, CSV, удаление
  styles.css               адаптивная светлая тема
scripts/                   импорт и сверка с исходным файлом
test/                      API и браузерные проверки
data/quiz.sqlite           автоматически создаваемая SQLite-база (не в Git)
```

Стек: **Node.js + Express + SQLite + HTML/CSS/Vanilla JavaScript**. Внешние сервисы, CDN и сборка frontend не нужны. `helmet` задаёт заголовки защиты и CSP; `express-rate-limit` ограничивает частоту запросов.

## Проверка и изменение ключа

**В исходнике правильные ответы не отмечены. Ключ составлен по содержанию вопросов и требует проверки владельцем перед официальным оцениванием.** Это не официальный ключ преподавателя.

Откройте `server/data/ANSWER_KEY_REVIEW.md`: там приведены вопрос, буква и полный текст выбранного правильного варианта. Рабочий файл — `server/data/answer-key.json`. Значения `A`, `B`, `C`, `D` соответствуют первому, второму, третьему и четвёртому вариантам исходного файла.

После редактирования ключа выполните `npm run check` и перезапустите сервер. Начатые попытки хранят серверный снимок вопросов и ключа; их оценка и исторические подробности остаются согласованными. Изменённый ключ применяется к новым попыткам. Если изменили ключ, обновите и таблицу проверки, чтобы она не устарела.

`npm run import:questions` повторно импортирует вопросы из `server/data/source.txt` **без перезаписи ключа**. `npm run check` сверяет все тексты и варианты с исходником.

## Данные и API

Таблица `attempts` содержит ID, имя, группу, начало/завершение (UTC), правильные/неправильные/пропущенные, процент, ответы JSON и серверный снимок теста. Процент = число правильных / 180 × 100, округление до двух знаков. Пропущенные не входят в число неправильных. В админке показываются только завершённые попытки; даты отображаются в часовом поясе браузера. CSV содержит даты UTC.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/questions` | Вопросы и варианты без ключа |
| POST | `/api/attempts` | `{name, group, version}` → ID, случайный токен, серверное время начала |
| POST | `/api/attempts/resume` | `{attemptId, token}` → состояние и вопросы сохранённой версии без ключа |
| POST | `/api/submit` | `{attemptId, token, answers: [{questionId, optionId}]}` → только подтверждение |
| POST | `/api/admin/login` | `{password}` → HttpOnly cookie сессии |
| POST | `/api/admin/logout` | Завершить сессию |
| GET | `/api/admin/session` | Проверить сессию |
| GET | `/api/admin/results` | Список: `search`, `sort=date` или `percentage`, `direction=asc` или `desc` |
| GET | `/api/admin/results/:id` | Подробности 180 вопросов и ключ сохранённой версии |
| DELETE | `/api/admin/results/:id` | Удалить результат |
| GET | `/api/admin/results/export.csv` | CSV с учётом поиска и сортировки |

Все изменяющие запросы требуют `Content-Type: application/json`. Повторная отправка одной попытки идемпотентна: результат не дублируется и не изменяется. Сервер не доверяет присланным баллам. Данные SQL передаются параметрами; сортировка ограничена разрешёнными столбцами. Пользовательские строки выводятся через `textContent`. CSV экранирует кавычки и формулы.

Ответы сохраняются в localStorage этого браузера; после отправки черновик очищается. Это не синхронизация между устройствами. При запрете localStorage интерфейс предупреждает о необходимости держать вкладку открытой. После перезапуска сервера администратору нужно войти снова (сессии хранятся в памяти, срок — 8 часов); попытки остаются в SQLite.

Для размещения в интернете используйте HTTPS, `COOKIE_SECURE=true`. `TRUST_PROXY=1` включайте только за одним доверенным reverse proxy, передающим `X-Forwarded-Proto` и реальный IP. Один процесс приложения достаточен для учебного проекта. Для резервной копии остановите сервер и скопируйте `data/` вместе с SQLite WAL/SHM-файлами, если они присутствуют. Незавершённые попытки также остаются в базе.

## Проверки

```bash
npm run check
npm test
npm run test:browser
```

Браузерный тест использует Playwright и Chromium по пути `/usr/bin/chromium`. При другом расположении: `CHROMIUM_PATH=/путь/к/chromium npm run test:browser`. Если Chromium не установлен, установите его для своей ОС. Скриншоты сохраняются в игнорируемый `test-artifacts/`. Проверки создают временные базы и удаляют их, не затрагивая рабочие результаты.

API-проверки: точность импорта, отсутствие ключа в публичных ответах, валидация, расчёт известной комбинации ответов, пропуски, поддельные баллы, повторная отправка, логин/выход, закрытые endpoints, детали, поиск по кириллице без учёта регистра, сортировка, CSV, запрет запросов с другого сайта, сохранение после перезапуска и удаление.

Браузерная проверка: настольная и мобильная страницы, выбор и изменение ответов, навигация, восстановление после reload, предупреждение о пропусках, отмена и подтверждение отправки, очистка localStorage, админка, все 180 подробностей, поиск, CSV и удаление с подтверждением.
